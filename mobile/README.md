# Patch Mobile

`mobile/` is the Patch client for iOS and Android. It is a real React Native
application built with Expo SDK 57 and Expo Router. Both platforms share the
same product structure and styling, with native platform behavior kept where it
improves the experience.

## Included experience

- Native email authentication, onboarding, SecureStore-backed sessions, and `patch://` auth callbacks.
- A shared Liquid Glass visual system: native iOS glass where supported and the same translucent language on Android.
- A five-tab app with Discover as the default: Discover, Map, an icon-only new-achievement action, Collection, and Profile.
- Instagram-style profile header and statistics, compact achievement tiles, and an ellipsis action menu.
- Square Apple Music-inspired Discover cards with right-to-like, left-to-dislike, up-to-skip gestures, tap-to-open details, and tap-to-open author profiles.
- Top-level activity inbox with realtime in-app notifications.
- Achievement creation with native location capture and an animated reward reveal.
- A custom Been-style SVG world map. Countries start gray and use persistent Patch-palette fills for Visited, Lived, and Wishlist. Continent progress, continent focus, pinch zoom, pan, and reset are included. No Google Maps or Apple Maps SDK is used.

## Architecture

- Expo SDK 57, React Native 0.86, React 19, and Expo Router.
- Supabase Auth, Postgres, Realtime, Storage, and Row Level Security.
- Reads and user-owned mutations use Supabase under RLS. Achievement creation
  and retry use authenticated Supabase Edge Functions backed by a durable
  Postgres generation queue; no provider secret enters the mobile bundle.
- `react-native-svg` renders the bundled country geometry from `@svg-maps/world` completely inside the app.

## Local setup

Prerequisites:

- Node.js 20.9 or newer and npm.
- Xcode with an iOS Simulator for iPhone development.
- Android Studio with Android SDK 36 for Android builds.
- The root Patch Supabase development services.

Start the backend from the repository root:

```bash
npm run supabase:start
npm run seed:local
```

For a hosted backend, create `mobile/.env` from `mobile/.env.example` and provide the browser-safe Supabase values. Local simulator commands obtain the current local Supabase values without writing secrets to a file. The iOS Simulator uses `127.0.0.1`; the Android Emulator uses its `10.0.2.2` bridge. A physical phone needs the Mac's LAN address and a development server reachable on that network.

Install and launch from the repository root:

```bash
npm --prefix mobile ci
npm run mobile:ios:local
npm run mobile:android:local
```

`npm run mobile:start:local` starts Metro with local backend values without launching a device. Use `mobile:ios` and `mobile:android` when values already come from `mobile/.env` or the build environment. This project uses native modules, so the development build is the authoritative runtime rather than Expo Go.

## Native projects and release builds

The `ios/` and `android/` directories are generated by Expo prebuild and intentionally ignored. Regenerate them after changing native dependencies or `app.config.ts`:

```bash
npm run mobile:prebuild
```

Bundle identifiers are `app.patch.mobile` on both platforms. `eas.json` contains development, internal preview, and production profiles. Store publishing, signing, APNs/FCM credentials, and EAS project linking are intentionally not performed from this workspace.

Before production distribution:

1. Apply all Supabase migrations, including `visited_countries` and achievement coordinates.
2. Add `patch://auth/callback` to the Supabase Auth redirect allow list.
3. Set hosted `EXPO_PUBLIC_SUPABASE_*` values in the build environment.
4. Configure Apple and Android signing plus APNs/FCM credentials.
5. Register device push tokens and add a server delivery worker for notifications received while the app is closed. The current activity inbox and foreground realtime notifications already work; remote background delivery still needs that production infrastructure.
6. Deploy the three achievement-generation Edge Functions and schedule the
   protected worker endpoint at least once per minute for process-death
   recovery.

## Validation

```bash
npm run typecheck
npm run lint
npx expo-doctor
npx expo export --platform ios
npx expo export --platform android
```

Native checks:

```bash
cd ios
xcodebuild -workspace Patch.xcworkspace -scheme Patch -configuration Debug -sdk iphonesimulator -destination 'platform=iOS Simulator,name=iPhone 17 Pro' CODE_SIGNING_ALLOWED=NO build

cd ../android
./gradlew assembleDebug
```
